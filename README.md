# Семейное древо

Статический сайт семейного древа на Vite и чистом JavaScript. Единственный источник данных для сайта — редактируемый файл `public/data/data.json`; при запуске и публикации данные из других файлов не генерируются.

Сайт содержит три страницы: «Древо», «Список» и «Всякое». На странице «Всякое» автоматически выводятся фамилии предков Павла Молчанова.

## Требования и команды

- Node.js 20+
- npm

```bash
npm install
npm run dev
npm run build
npm run preview
```

После редактирования JSON перезапустите страницу браузера. Перед публикацией проверьте проект командой `npm run build`, затем сохраните изменения коммитом и отправьте их в `main`.

## Редактирование данных

Откройте `public/data/data.json`. Корневой объект содержит два массива:

- `people` — люди и их сведения
- `families` — связи супругов и детей

Не редактируйте JSON через таблицу или YAML-конвертер без проверки результата: синтаксис должен оставаться корректным JSON. Строки и ID заключайте в двойные кавычки, между свойствами ставьте запятые. После правок проверьте сборку.

### Добавить человека

Добавьте запись в `people`. У каждого человека должен быть уникальный `id`. Поля `name`, `given`, `surname`, `sex`, `birthDate`, `birthPlace`, `deathDate`, `deathPlace`, `living`, `occupation`, `notes`, `families` и `extra` используются сайтом. Неизвестные значения можно оставить пустыми (`""`), заметки — пустым массивом.

```json
{
  "id": "I900001",
  "name": "Иван Иванов",
  "given": "Иван",
  "surname": "Иванов",
  "sex": "M",
  "birthDate": "1900",
  "birthPlace": "Москва",
  "deathDate": "",
  "deathPlace": "",
  "living": false,
  "occupation": "",
  "notes": [],
  "families": {
    "spouse": ["F900001"],
    "parent": []
  },
  "media": [],
  "extra": {
    "comment": "Краткий комментарий",
    "details": "Подробное описание в Markdown.",
    "photo": "main.jpg",
    "gallery": ["gallery-1.jpg"],
    "link": "",
    "wikipedia": "",
    "list": true,
    "clan": "Род Ивановых"
  }
}
```

Для живого человека укажите `"living": true` и не публикуйте день или месяц рождения: все сведения в этом JSON доступны посетителям сайта.

Чтобы изменить человека, отредактируйте его запись. Чтобы удалить — удалите запись из `people` и проверьте связанные с ним записи в `families`, чтобы не осталось ссылок на отсутствующий ID.

### Добавить или изменить род в списке

Название рода задаётся в `extra.clan` записи человека. Чтобы переименовать род или переместить человека в другой, измените значение `clan`. Название группы создаётся автоматически, когда оно указано хотя бы у одного человека.

- Люди с указанным `clan` попадают в список только при `"list": true`.
- Люди без `clan` попадают в группу «Без рода», если `"list": false` не задано.
- `"list": false` исключает человека из списка независимо от рода.
- Поставьте `"list": true`, чтобы добавить человека с родом в список.

Пример:

```json
"extra": {
  "list": true,
  "clan": "Род Ивановых"
}
```

### Добавить семейные связи

Добавьте запись в массив `families`, используя ID существующих людей. Значения `husband`, `wife` и `children` должны совпадать с `people[].id`. Пример объекта:

```json
{
  "id": "F900001",
  "husband": "I900001",
  "wife": "I900002",
  "children": ["I900003"],
  "marriageDate": "",
  "marriagePlace": "",
  "divorceDate": ""
}
```

Массив `families` управляет связями на древе. Свойства `people[].families` хранят дополнительные ссылки, но сами связи для визуализации строятся по объектам в `families`.

### Фото и логотип

- Основное фото: `public/photos/<ID>/main.jpg`; имя файла укажите в `people[].extra.photo`.
- Галерея: храните файлы в `public/photos/<ID>/` и перечислите их в `people[].extra.gallery`.
- Логотип шапки: `public/assets/logo.png`. Если файла нет, отображается текст «Семейное древо».

Пути к фотографиям регистрозависимы при публикации. Перед добавлением фото рекомендуется уменьшить длинную сторону до 1600 px, сохранить в JPEG с качеством около 80% и по возможности уложиться в 300 КБ. Репозиторий лучше держать меньше 1 ГБ.

## Публикация на GitHub Pages

1. В GitHub откройте **Settings → Pages → Build and deployment → Source** и выберите **GitHub Actions**.
2. Отправьте изменения в ветку `main`.
3. Workflow `.github/workflows/deploy.yml` выполнит `npm ci`, `npm run build` и опубликует `dist`.

Сайт будет доступен по адресу `https://<user>.github.io/<repo>/`.

## Приватность

`public/data/data.json` и всё содержимое `public/` доступны всем посетителям сайта. Проверяйте и удаляйте из JSON частные сведения, которые не должны быть публичными. Не кладите GEDCOM, пароли, адреса электронной почты или другие приватные данные в `public/`. GEDCOM-файлы игнорируются Git через `.gitignore`.
